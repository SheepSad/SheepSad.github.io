# 可定制个人主页（HTML / CSS / 原生 JS）

一套**未编辑状态即为占位内容**的个人主页：打开就能看到完整排版，所有文字、头像、技能、项目、联系方式、音乐都在「设置页」里改，改完刷新即生效。含**白日 / 黑夜**两套现代化简约 UI 与完整切换动效。

```
homepage/
├─ index.html          主页：左栏（设置按钮 / 圆形头像+姓名 / 音乐播放器 / 浮层歌词）
│                      + 右栏（个人简介 → 自身技能 → 个人项目 → 联系方式）
├─ settings.html       设置页：左侧导航切换板块，右侧编辑内容
├─ content.json        ★ 站点默认内容：线上访客首次打开时自动载入（部署必读，见第六节）
├─ 404.html            404 页面：自动跳回站点首页（子路径部署也能正确回主页）
├─ .nojekyll           关闭 GitHub Pages 的 Jekyll 处理，保证静态文件原样发布
├─ css/
│   ├─ theme.css       设计令牌、白日/黑夜双主题、@property 颜色插值、通用组件与动画
│   ├─ main.css        主页排版（网格合并注释都在这个文件顶部与各布局节点上）
│   └─ settings.css    设置页排版
└─ js/
    ├─ store.js        数据层：默认数据 / localStorage / IndexedDB 音乐仓库 / 事件总线
    ├─ theme.js        主题引擎：手动按钮切换、跟随电脑时间自动切换、三种切换特效
    ├─ main.js         主页渲染 + 音乐播放器 + 歌词滚动
    └─ settings.js     设置页全部编辑逻辑
```

## 一、打开方式

直接双击 `index.html` 即可使用（全部为传统 `<script>`，不用 ES Module，所以 `file://` 也能跑）。

> 想让**导入的音乐在关闭浏览器后依然保留**，建议用本地服务器打开：部分浏览器不允许 `file://` 页面使用 IndexedDB。
> 任选一种：
> ```bash
> npx serve homepage          # 或用 python -m http.server 8080
> ```
> 之后访问 `http://localhost:端口/index.html`。若在 `file://` 下导入音乐，页面会提示"仅本次会话有效"，功能本身不受影响。

## 三、主题切换动效是怎么做的

1. **颜色全局流动**：在 `theme.css` 用 `@property` 把 `--bg / --text / --surface / --accent …` 注册成真正的 `<color>` 类型属性，
   再在 `:root` 上写 `transition: --bg var(--dur) …`。切换时只改 `<html data-theme="dark|light">`，
   所有用到 `var(--token)` 的地方（背景、文字、卡片、按钮、光斑、进度条、网格线）会在同一时间平滑插值，不会"跳"。
2. **切换特效**（设置页可选）：
   - `ripple` 波纹扩散：从点击位置炸开一圈强调色光波；
   - `wipe` 圆形擦除：新主题背景以圆形 clip-path 铺满全屏后再揭开，浏览器支持时走原生 `View Transitions`；
   - `fade` 柔和淡入淡出：一层与目标主题同色的薄幕呼吸一次。
3. **内容层微动效**：切换瞬间 `body.is-switching` 让整页轻微缩放 + 模糊，掩盖颜色插值的中间态。
4. **自动模式**：每 30 秒检查一次系统时间，跨过设定节点自动切换；标签页从后台切回时立即校正。
5. **降级**：不支持 `@property` 的浏览器仍能切换（只是颜色直接变化），特效层照常播放；系统开启「减弱动态效果」时自动关闭动画。

主页右上角的昼夜按钮：`手动模式` 下点一下即切换；`自动模式` 下点一下会接管为手动模式并切到相反主题（有提示）。
快捷键 `Shift + D` 同样可以切换昼夜。

### 3.1 配色预设与自定义（外观主题 → 视觉细节）

**默认是「原生新拟物」—— 也就是 `css/theme.css` 里原本写死的那套冷灰蓝皮肤，一个令牌都不覆盖。**
换配色是可选功能，不会动到原有设计。

| 选项 | 说明 |
| --- | --- |
| 强调色 | Apple 系统色板 8 色，**含石墨灰 `#8e8e93` 与银白 `#c7c7cc`** —— 想要整页灰白极简就选它们；也可任意自定义 |
| **配色预设** | 6 套预设，每套都自带「白天 + 黑夜」两种底色写法与配套强调色，见下表 |
| 自定义颜色 | 背景 / 文字各两枚取色芯片（白天、黑夜），改动任意一项会自动切到「自定义」预设 |
| 圆角大小 | 0–36px |
| 切换动效时长 | 180–1400ms |
| 界面动效 | 总开关，关闭后所有过渡与滚动动画停止 |

| 预设 | 白天 | 黑夜 | 配套强调色 |
| --- | --- | --- | --- |
| 原生新拟物（默认） | `#e8edf5` | `#14161c` | Apple 系统蓝 |
| Apple 简约灰白 | `#f5f5f7` | `#1c1c1e` | 石墨灰 |
| 暖阳米白 | `#f7f3ec` | `#1b1714` | 橙 |
| 墨玉深灰 | `#ececee` | `#131315` | 中灰 |
| 深海夜蓝 | `#eaeff7` | `#0d1219` | 系统蓝 |
| 自定义 | 自己挑 | 自己挑 | 保持不变 |

> 毛玻璃强度调节已下线（新拟态皮肤不需要调模糊），`--blur` 改为 CSS 固定值，只留给 toast 之类的浮层使用。

**装饰光斑跟随强调色**：`--blob-1/2/3` 在 `theme.css` 里由 `color-mix()` 从 `--accent` / `--accent-2` 推导，
所以改强调色时，背景那三团光晕会一起变（不支持 `color-mix` 的老浏览器回落到固定值）。

**为什么换底色会自动连带一堆颜色**：这套 UI 是新拟态（Neumorphism），铁律是「表面色 = 背景色」，
立体感完全由一对互补阴影（左上受光 + 右下背光）制造。所以一旦选了非原生预设，以下令牌会被重新推导，
否则控件会变成浮在背景上的补丁：

```js
// js/theme.js deriveTokens()  —— preset 为 native 时直接返回 null，不注入任何覆盖
'--surface':   背景色本身            // 表面 = 背景
'--surface-2': 背景色 ±3%            // 凹槽：亮底压暗 / 暗底抬亮
'--bg-2':      背景色向白偏移        // 浮起面（弹层、下拉选项）
'--muted':     字体色 62% + 背景色 38%
'--border' / '--track' / '--ink-line': 字体色的低透明度版本
'--sh-light' / '--sh-dark': 预设自带（原生/Apple/暖阳各有一套色调），自定义时按背景亮度自动判定
```

覆盖只写在注入的 `<style id="dsh-color-overrides">` 里，两套主题各一组规则
（`:root{…}` 与 `[data-theme="dark"]{…}`），所以白天与黑夜可以各自拥有不同的底色；
选择「原生新拟物」时该样式表会被清空，页面回到 `theme.css` 的原始取值。

## 四、网格合并（Grid Merge）代码注释导览

`css/main.css` 顶部有完整速查表，常用几种：

```css
/* ① 命名区域合并：同名字符串自动合并成一整块区域 */
.shell {
  grid-template-columns: 330px minmax(0, 1fr);
  grid-template-areas: "sidebar content";
}
.sidebar { grid-area: sidebar; }
.content { grid-area: content; }

/* ② 横向合并 2 列 / ③ 纵向合并 2 行 / ④ 2×2 合并四格 */
.skill-card[data-size="wide"] { grid-column: span 2; }
.skill-card[data-size="tall"] { grid-row: span 2; }
.skill-card[data-size="big"]  { grid-column: span 2; grid-row: span 2; }

/* ⑤ 整行合并：从第一条列线到最后一条列线 */
.skills-empty { grid-column: 1 / -1; }

/* ⑥ dense 回填：合并留下的空洞自动被后面的卡片补上 */
.skills-grid { grid-auto-flow: dense; grid-auto-rows: 112px; }
```

设置页「自身技能 → 卡片尺寸」直接对应上面四种合并方式；窄屏下会自动取消合并，避免隐式列把卡片挤出屏幕。

## 五、数据存储说明

| 内容 | 存放位置 | 说明 |
| --- | --- | --- |
| 文字 / 主题设置 / 曲目信息 | `localStorage`（键 `dsh.home.v1`） | 每次修改自动保存（120ms 防抖） |
| 头像图片 | `localStorage` | 导入时自动居中裁剪 + 压缩成 400px JPEG（约 20–40 KB） |
| 音乐文件 | `IndexedDB`（库 `dsh-home-db`） | 二进制大文件，不占 localStorage 配额 |
| 是否被访客改过 / 已装载的内容版本 | `localStorage`（键 `dsh.home.meta.v1`） | 只有改动「资料/技能/项目/联系方式/曲库」才算改过内容；主题等偏好不影响 |
| 首屏配色快照 | `localStorage`（键 `dsh.home.themecss.v1`） | 两个页面的 `<head>` 里有一小段内联脚本，在首次绘制前贴出上次算好的整套令牌，避免"先原生配色、再渐变到预设"的闪回 |
| 装载时的版本判定 | `localStorage`（键 `dsh.home.meta.v1` 的 `seededAt`） | `content.json` 的 `updatedAt` 与它相同 → 不重新装载（本地改动保留）；不同 → 作者的默认值整份生效（含循环模式、主题） |

- **两个页面实时同步**：设置页保存后，已打开的主页标签页会自动刷新（`storage` 事件）。
- **备份**：设置页「数据与备份」可导出 JSON（不含音乐文件），换浏览器时导入即可恢复文字内容。
- **清空**：同一面板可「恢复默认」或「清空曲库」。

## 六、部署到 GitHub Pages（重要）

### 为什么部署后"和本地不一样"

这个主页的内容不是一个写死在 HTML 里的字符串，而是**存在浏览器的本地存储里**：

| | 本地（file:// 或 localhost） | 部署后（https://用户名.github.io/仓库名/） |
| --- | --- | --- |
| `localStorage` | 你编辑的姓名 / 简介 / 技能 / 项目 / 联系方式 | **是空的**（不同域名 = 不同存储空间） |
| `IndexedDB` | 你导入的 mp3 | **是空的**（音乐文件根本没上传） |

所以直接 `git push` 之后，线上访客（包括换台电脑的你自己）看到的是**未编辑的占位模板**，而不是你精心填好的页面。
这不是样式丢失，而是"内容没有跟着代码一起上线"。

### 正确做法：把内容导出成 `content.json`

站点已经内置了这套机制：**访客第一次打开页面时，会自动读取仓库同目录下的 `content.json` 作为站点内容**；
如果访客自己改过内容，则不再覆盖他的改动；你后续更新 `content.json`（`updatedAt` 变化），没改过的访客会自动跟进最新版。

操作步骤：

1. 在本地把主页编辑好（设置页里改文字、传头像、加技能、加项目、填联系方式）；
2. 设置页 →「数据与备份」→ 点 **导出为站点默认内容（content.json）**；
3. 把下载到的 `content.json` 放到仓库里 **和 `index.html` 同一层**，与 `index.html`、`settings.html`、`css/`、`js/` 一起提交：

   ```
   仓库根目录/
   ├─ index.html
   ├─ settings.html
   ├─ content.json      ← 放这里
   ├─ 404.html
   ├─ .nojekyll
   ├─ css/ …
   ├─ js/ …
   └─ audio/            ← 音乐文件也一起提交（见下一步）
   ```
4. 音乐：`IndexedDB` 里的音频不会上线，请把音频文件放进仓库（例如 `audio/` 目录），
   再到设置页「音乐播放器」给每首曲子填写 **音频地址**（如 `audio/song.mp3`，或一个 https 外链）。
   播放器会优先使用这个地址，本地导入的文件仍然照常可用。
5. 打开线上地址验收；如果看到的是旧样子，按 <kbd>Ctrl</kbd>+<kbd>F5</kbd> 强制刷新（GitHub Pages 资源默认缓存 10 分钟）。

> **改了代码，线上却没变化？** 先核对版本号，别怀疑逻辑：
> 控制台执行 `DSH.version`，或看设置页「数据与备份 → 当前状态」里的 **前端版本** 一行，
> 与仓库里的 `js/version.js` 对比 —— 不一致就是缓存没更新（GitHub Pages 的 HTML 默认缓存 10 分钟，
> 浏览器可能更久）。按 <kbd>Ctrl</kbd>+<kbd>F5</kbd> 强制刷新，或用无痕窗口打开确认。
> 每次改完代码记得把 `index.html`、`settings.html` 里脚本的 `?v=` 和 `js/version.js` 一起改掉。

> **没上传 `content.json` 会怎样？** 访客（包括你自己换设备后）打开线上站点时，
> 看到的就是内置示例内容（"你的名字 / 示例技能"），主页右侧看起来像"信息全没了"——
> 内容其实没丢，只是仓库里没有那份数据。这时主页右下角会弹一句
> **「没找到 content.json，当前显示的是示例内容」**，见到它就说明是漏传了。

> **改过主题/循环模式会不会让 `content.json` 失效？** 不会——两者互不干扰，规则只有一条：
> **`updatedAt` 没变 → 不重新装载**，所以日常在主页与设置页之间来回走、刷新页面，
> 都不会动你在设置里改过的循环模式、主题等；
> **`updatedAt` 变了（你重新导出）→ 作者的默认值整份生效**，包括 `music.loop`、`theme`。
> 也就是说：想让"列表循环"成为线上默认，就把循环模式调成列表循环再导出一次。
> 若只想让自己这台浏览器立刻恢复成仓库里的默认值（不重新导出），
> 用设置页「数据与备份 → **重新载入站点内容**」按钮即可。
> 早期版本动过任何设置都会置 `dirty`，从而永久挡住 `content.json` —— 现在有两条自愈：
> 本地内容与内置示例一致、或从未装载过且没有任何个人信息时，会自动清掉这个假标记；
> 另外每次装载都会比对"本地内容是否与仓库里的完全一致"，一致也会清掉。
> 如果确实想强制拉一次线上内容，设置页「数据与备份」里有 **重新载入站点内容** 按钮。

设置页「数据与备份 → 当前状态」会实时告诉你：现在是不是 http(s) 环境、本地内容是否已被你改过、音乐来源是否已配好。

### 部署方式

**A. 用 Git 推送（推荐）**

```bash
cd 你的仓库
git add .
git commit -m "deploy personal homepage"
git push
```

然后在仓库 **Settings → Pages** 里把 Source 设为 `Deploy from a branch`，分支选 `main`、目录选 `/ (root)`（若主页放在子目录，则选 `/docs` 或对应目录）。
几分钟后访问 `https://用户名.github.io/仓库名/`。

**B. 直接在网页上传**
把 `index.html`、`settings.html`、`content.json`、`404.html`、`.nojekyll` **以及 `css/`、`js/` 两个文件夹**一起拖进仓库。
⚠️ 只上传 html 会变成"没有样式的裸页面"——目录结构必须保留（`css/` 与 `js/` 不能少）。

### 已经处理好的部署细节

| 细节 | 处理方式 |
| --- | --- |
| 子路径部署（`/仓库名/`） | 所有资源引用都是相对路径，`css/`、`js/`、`settings.html`、`content.json` 全部跟着当前目录走 |
| 大小写敏感（Linux 服务器） | 文件名与引用全部小写且完全一致（已逐条校验） |
| Jekyll 处理 | 仓库里放了 `.nojekyll`，静态文件原样发布，不做 Liquid 解析 |
| 打开不存在的地址 | `404.html` 会向上探测并跳回站点首页，子路径 / 自定义域名都适用 |
| 改完代码浏览器还用旧的 | 页面引用带 `?v=2` 版本号；**以后改了 `css/`、`js/`，请把两个 html 里的 `?v=2` 一起 +1** |
| 老浏览器掉色（Safari < 16.2 / Firefox < 113） | `color-mix()` 相关颜色都写了 `@supports` 兜底值，不会因为不支持而变成透明 |

## 七、其他细节

- 空格键播放 / 暂停，`Shift + D` 切换昼夜；卡片支持键盘 Tab + Enter。
- 项目 / 联系方式卡片带鼠标跟随光斑（`--mx/--my`）与悬浮抬升。
- 歌词支持两种写法：LRC 时间轴（`[00:12.30]歌词`）或纯文本（按歌曲总时长自动均匀铺开）。
- 歌词栏只完整显示两行：**当前句 + 下一句**（双语歌词里通常就是翻译行），上一句直接隐藏，
  第三行及以后保持虚化（`main.css` 的 `.lyric-line.is-active / .is-next / .is-prev`；
  视口高度与顶部内边距由 `.lyrics__viewport` 的 `height` 与 `--lyric-top-pad` 控制，JS 会自动读取）。
- 曲目的 `src` 字段：填了就用该地址播放（线上可用），没填才回落到 IndexedDB 里的本地导入文件。
  **只写文件名也能用**：若 `src` 里没有目录、也不是 `http(s)/data` 链接，播放器会先探测
  `audio/` 目录下有没有同名文件（HEAD 请求，结果有缓存），有就用它，没有才按原样使用 ——
  这样设置页里只填「歌名.mp3」也能在线上正常播放。
- 滚动渐入（`.reveal`）：首屏之外的元素滚到才淡入上浮；**联系方式板块例外**，
  页面一渲染就浮现（`renderAll()` 里的 `revealNow('#sec-contact')`），
  因为它在页面最底部，如果等滚动，首屏底部会先留一块看不见的空白。
  观察器本身也放宽成 `rootMargin: 0 / threshold: 0`，只要露头就浮现。
- 播放器唱片不再是头像照片，而是**彩色胶皮唱片**：`radial-gradient` 出唱片本体（强调色，中心略深），
  叠一层 `repeating-radial-gradient` 音槽与一道 `conic-gradient` 高光（旋转时才看得出在转），
  再加中心圆标与轴孔；换强调色整张唱片跟着换色。
- 循环模式在主页面就能切：`#loopBtn` 点一下走 列表 → 单曲 → 随机，非默认模式时按钮点亮成强调色，
  换页后设置页的分段控件也是同一个值（都存 `music.loop`）。
- 无外部依赖、无 CDN、无需构建，全部内联 SVG 图标。
- 响应式：≤980px 侧栏与内容区合并为单列，≤560px 进一步收紧字号与间距。
- 浏览器控制台里可用 `DSH.store`（数据）、`DSH.theme`（主题）、`DSH.player`（播放器）调试或二次开发，例如
  `DSH.theme.apply('dark')`、`DSH.player.load(0, true)`、`DSH.store.loadSiteContent({force:true})`。
